## Demo 完成定义

完整 demo 是一条可以演示、复查和复现的端到端闭环：

1. 读卡器在断公网时读取 RFID 标签，识别已绑定绘本并读取本地 StoryPack。
2. 阅读器播放绘本内容、获取儿童朗读音频、更新阅读位置；位置不确定时保守冻结。
3. 儿童可以就当前绘本提问；回答只使用 StoryPack 中可追溯的证据，无证据时明确拒答；答案可离线播报。
4. 阅读结束后，阅读器保存摘要和证据；HarmonyOS 家长端可以连接、同步、查看并复核位置。
5. 复核状态可以在配对客户端之间同步，应用重启后仍能读取已同步的记录。
6. 使用真实 Hi3516、RFID、麦克风、扬声器和鸿蒙手机完成方案书规定的 G0—G5 实物验收。

完成条件：本清单所有必做未完成项都变为已完成，并且每项都有测试或实物验收证据。电脑模拟器和 QEMU 只证明各自的软件范围，不能代替真实儿童音频、开发板外设、板端性能或手机真机验收。

首个 demo 的内容范围是作者录入并审核的 StoryPack。PDF/OCR 自动编排、通用大模型问答和勋章完整业务规则不属于首个 demo 的验收范围；能力雷达和勋章目前是界面预览。本计划额外跟踪一个 PC 离线语义问答演示原型；它使用受限关系识别和证据模板，不代表通用生成式问答，也不替代板端验收。

## 运行与检查

使用 DevEco Studio 打开仓库，安装 HarmonyOS SDK API 26（兼容版本和目标版本均为 26.0.0），选择 entry 模块和 default 产品后构建运行。项目不包含签名密钥，输出为 unsigned HAP。

Hvigor 构建：

~~~text
hvigorw --mode module -p product=default -p module=entry@default assembleHap
~~~

Windows Python 回归：

~~~powershell
py -X utf8 -B -m unittest discover -s tools -p "test_*.py" -v
~~~

StoryPack 导入回归：

~~~powershell
py -X utf8 -B -m unittest discover -s tools -p test_storypack_import.py -v
~~~

家长端服务和复核跨端检查需要 DevEco 自带 Node.js / TypeScript；路径按本机安装位置调整：

~~~powershell
& 'D:\DevEco Studio\tools\node\node.exe' tools/test_parent_services.cjs 'D:\DevEco Studio\sdk\default\openharmony\ets\build-tools\ets-loader\node_modules\typescript'

$env:TONGYUE_TYPESCRIPT = 'D:\DevEco Studio\sdk\default\openharmony\ets\build-tools\ets-loader\node_modules\typescript'
$env:TONGYUE_NODE = 'D:\DevEco Studio\tools\node\node.exe'
py -X utf8 -B -m unittest discover -s tools -p test_parent_review_e2e.py -v
~~~

Linux/WSL 虚拟板、ARM/QEMU、PC CTC 和真机验收命令见 [RFID_MVP.md](docs/RFID_MVP.md) 与 [CTC_PC.md](docs/CTC_PC.md)。
